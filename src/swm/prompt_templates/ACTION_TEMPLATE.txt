These are scenario-specific examples, not a complete domain. Select and adapt them using PREDICATE_TEMPLATE and RULES; examples omit merge-generated numeric suffixes and select one causal variant per action. When combining examples, maintain every tracked predicate in all relevant actions. An object's category alone does not require clear. Once clear is tracked for an object, maintain it in every relevant pickup, release, handoff, and upper-load change, including releases onto ordinary supports. Keep it false while any hand directly holds the object.

The strict stack examples below assume each base has at most one direct upper load and remains unheld while loaded. Establish these invariants from the initial state and all relevant actions before using their unconditional clear-restoration effects. For multiple loads or supports, update the actual affected objects and restore clear only after the last upper load is removed and the object is unheld. Use uncovered separately when a task needs container-opening access, including access to a held container.

Faucet examples that retain water assume one empty receiver and one initially undelivered portion, with no refill in that scenario. Repeated fills or multiple receivers require guards derived from the actual portion lifecycle.
