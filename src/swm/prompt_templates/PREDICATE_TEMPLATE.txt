Vocabulary and predicate-specific constraints; select needed entries under RULES, not a complete domain to copy.

(:predicates
  ; Static categories and structural/supply/control relations
  (hand ?h)
  (part_of ?p ?w) ; Component or spatial position p belongs to whole w.
  (dispenses ?s ?m) ; Supply capability, not availability of a discrete portion.
  (controls ?c ?d) ; Control c operates device d.

  ; Hand resources
  (hand_free ?hf) ; Neither holding an object nor sustaining button control.
  (holding ?h ?o)
  (pressing ?h ?b) ; Sustained button control occupies hand h until release.

  ; Tool grip
  (grip_free ?gf) ; Active one-payload tool grip is free; required to put the tool down.
  (gripping ?t ?o) ; Acquiring a payload replaces grip_free with gripping; release reverses it. The hand still holds the tool.

  ; Location and insertion
  (on ?o ?s) ; Direct support without a modeled fine-grained position.
  (in ?c1 ?c2) ; c1 is directly contained in c2, including actual nesting; containment does not imply closure.
  (inserted ?o ?s) ; Insertion is distinct from support and containment.
  (at ?o ?p) ; Fine-grained surface position: declare (position ?p) and static (part_of ?p ?s). at replaces on for that placement rather than duplicating it.

  ; Location supplements: alignment and relative position
  (under ?o ?r)
  (aligned ?o ?r)
  (beside ?o ?r)
  (left_of ?o ?r)
  (right_of ?o ?r)
  (centered ?o ?r)

  ; Mutually exclusive state pairs
  (open ?o)
  (closed ?c)
  (is_on ?io)
  (is_off ?io)
  (locked ?l)
  (unlocked ?u)
  (pressed ?p)
  (unpressed ?u)
  (folded ?f)
  (unfolded ?u)

  ; Stack and opening access
  (clear ?c) ; No direct upper load and no hand directly holding the object. Actual nested stack members count as loads; ordinary contents do not. Use only for necessary stack constraints: strict single-item pickup or stacking directly onto an object, not ordinary multi-object surface placement. Load-preserving operations use their own guards; not clear does not prove a load.
  (uncovered ?u) ; No object occludes the opening; ordinary contents need not obstruct it. Use only for opening access beyond open/closed and independently of stack access: a held container can be uncovered while clear is false.

  ; Contents and fill level
  (empty ?e) ; No direct in contents of any modeled kind.
  (filled ?f) ; Required fill level reached, not merely nonempty.

  ; Directional motion-path clearance
  (opening_clear ?oc) ; Opening path has no blockers; distinct from empty, clear, and uncovered. Does not imply closing_clear.
  (closing_clear ?cc) ; Closing path has no blockers; distinct from empty, clear, and uncovered. Does not imply opening_clear.
  (blocks_opening ?b ?u) ; b obstructs opening unit u.
  (blocks_closing ?b ?u) ; b obstructs closing unit u.

  ; Pose pairs by dimension
  (upright ?u)
  (upside_down ?ud)
  (flat ?f)
  (vertical ?v)

  ; Process results
  (heated ?h) ; Heating differs from boiling.
  (boiled ?b) ; Completed boiling of this discrete material portion.
  (rinsed ?r) ; Rinsing, wiping, and cleanliness are distinct.
  (wiped ?w)
  (clean ?c)
  (wet ?w)
  (stirred ?s)

  ; Material state and composition
  (hot ?m) ; Currently hot; distinct from having been heated.
  (cold ?m) ; Currently cold.
  (warm ?m) ; Task-required warm temperature; not implied by mixing.
  (mixed ?m) ; Task-required mixture; does not imply temperature or fill level.
)
