# Task
Audit the full Generator ledger for decisive edits to its chronological Drafts. Follow each object's source, control, use, handoff, and release; preserve a Draft unless the trajectory establishes an error.

# Inputs
Instruction: {instruction}

Chronological Generator ledger:
{evidence_ledger}

Attached image: the episode's initial frame, G0 ({initial_frame}).

# Audit
- Observations and Drafts are fallible. A shared img_N is one physical state: resolve conflicting descriptions using the surrounding before/after states, not by inserting an intermediate action. Use the initial image only for initial identity/state.
- The instruction guides attention and compatible naming; it cannot prove an unseen event or remove an extra observed event.
- Track object identity/count, controller, direct support/containment, payload, and affected part. Handoff preserves payload identity and is a completed action. In stacking, the new top object becomes the next direct target. Delete a counted extra only with evidence of duplication.
- If control switches from held A to controlled B, A's control ended. Insert Place when A is visibly supported; if A leaves view and continued holding/handoff is impossible, use `Set down A` without inventing a location.
- Preserve real repeats, reversals, acquisitions, handoffs, uses, placements, starts/stops, and final operations. Across groups, rising fill, repeated strokes, or increasing effect under continuous control are progress, not new occurrences. Merge fragments only without stable release/reset followed by renewed actuation or a distinct new task result. A no-result trial is incomplete; retain the later completed actuation. Identical wording on different affected parts does not prove duplication.
- Audit every use or Place for its earlier independently evidenced acquisition, including small payloads loaded onto tools. Pick requires the object itself to leave direct support under control: insert an omitted Pick at the observed support loss, not from Place alone. Delete a premature Pick contradicted by continued support, preserving a later real Pick. Supported Grasp counts only when control persists across independent task operations, not for momentary contact. Keep acquisition, use, handoff, and placement distinct.
- If the initial frame already holds a task object and its first trajectory ends in placement, insert acquisition only when the instruction names it and a unique compatible source is visible.
- When adjacent groups disagree at their shared img_N about release versus continued control of the same object, reconstruct one transfer: preserve the earlier acquisition and the later stable placement, deleting intermediate Place/Pick fragments.
- Track payload independently from its carrier. Once loading is established, carry it forward until observed unloading or contradiction. A negative transfer claim based only on invisible payload is not evidence; require incompatible carrier-opening/target geometry or later visible retained payload. For an instructed transfer, alignment over the named target, opening-down orientation, then return upright or set-down establishes a small or sparsely sampled transfer; insert it without replacing the carrier's final Place. Later unloading from a tool establishes its earlier source-to-tool loading when preceding source contact is recorded.
- Track doors and lids by whether the interior is exposed or covered, not by screen orientation. If the ledger establishes fully exposed interior followed by the door/lid covering it before an exterior control action, insert Close before that action.
- Contact alone is not Press; require control motion or compatible device response. Identify the affected physical part rather than borrowing a later control's name; combine each actuation with its delayed response, but preserve separate completed actions on different parts.

# Edits
Insert only an observed omitted operation at its completion group. Replace only an established operation/object/actor/direct-source/target/boundary error. Delete only an established duplicate, contradiction, unfinished fragment, or incidental motion. Otherwise preserve the Draft. Equivalent wording and faithful macros are valid.

New action text is one concise sentence with minimum distinguishing qualifiers and direct source/target. Never include G#, K#, img_#, or evidence text.

# Output
Return JSON immediately with no prose:
{{"decisions":[{{"reason":"G1 img_57->img_70 shows ...","op":"replace","draft":2,"group":1,"action":"..."}}]}}

Each decision has exactly these five fields. `op` is `insert`, `replace`, or `delete`. `draft` is the original target ID, or preceding original ID for insert (`0` before D1). `group` is the target Draft group for replace/delete and evidence group for insert. `action` is one line for insert/replace and `null` for delete. Every reason must contain literal G# and img_N->img_M and use at most 25 words.

Use original IDs without renumbering; replace/delete each Draft at most once. Inserts keep original positions and listed order. Result groups must be nondecreasing. If no edit is justified, return {{"decisions":[]}}.
