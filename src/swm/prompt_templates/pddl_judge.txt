Judge whether an embodied robot plan is executable and fully satisfies the instruction.

# Inputs

- Instruction:
{instruction}

- Ground-truth reference plan:
{kf_plan}

- Evaluated plan:
{nl_plan}

- Initial scene image: attached.

# Evidence Model

- The Instruction is authoritative about what must be achieved, including any specified object, scope, method, tool, quantity, order, final relation, cleanup, return condition, or persistence.
- The reference plan is one valid witness. Use it to infer relevant state changes and causal dependencies, but do not require its wording, incidental details, specific actions, or total order unless they are necessary from the Instruction or action semantics.
- The image grounds object identities and the observable initial scene. An unclear image cannot overturn a necessary causal condition established by stronger evidence.
- Other facts are unknown. Reject only when failure follows from the provided evidence or unambiguous action semantics. Do not invent hidden actions, hidden states, or unsupported physical constraints.

# Plan Comparison Rules

- Compare state transitions and task-relevant conditions, not text.
- Accept supported aliases, paraphrases, independent reordering, harmless redundancy, and alternative paths that establish the same necessary states.
- Do not treat an action as necessary merely because it appears in the reference plan.
- An action includes its inherent direct effects, but not separate acquisition, access, relocation, release, opening, closing, or other independently meaningful actions.
- State persists until changed by a later action.
- Direct support, containment, possession, and other typed relations are not interchangeable or transitive unless explicitly supported.
- Instruction-required methods, tools, quantities, order, cleanup, return conditions, and persistence requirements cannot be replaced merely by reaching a similar final state.

# Evaluation

Perform the following checks in order:
1. Build the complete task contract from the Instruction.
2. Derive only the prerequisites, effects, and partial-order dependencies that are necessary for execution or for satisfying that contract, using the Instruction, reference plan, image, and unambiguous action semantics.
3. Simulate the Evaluated plan from the initial scene in order, tracking all task-relevant state, including access, possession, direct location, object relations, and device state.
4. At each action, check whether its necessary preconditions are satisfied by the accumulated state.
   - If a precondition is definitely unsatisfied, stop at the earliest such action and classify the plan as an execution failure.
   - Do not reject merely because a condition is unknown or unclear.
5. Only if the entire plan is executable, verify whether the resulting state and action history satisfy the complete task contract.

Before rejecting, verify that the disputed condition is actually necessary and ground the conclusion in decisive input evidence.

# Output

Return exactly this JSON object and no additional text or fields:

{{
  "reasoning": "detailed, evidence-grounded evaluation; for failure, identify the decisive execution or completeness issue",
  "pass": true or false,
  "feedback": "empty if pass=true; otherwise, briefly identify the erroneous step or unmet requirement"
}}
