# Audit

## 1. Contract

Extract required objects, quantity, operations, source, destination, relation, method, explicit order, cleanup, and persistent result.

- Every imperative operation needs a Candidate action even if its result already holds initially; facts are not performed actions. For processes at distinct physical sites (e.g. outlets), verify the object is positioned at each site when its operation occurs.
- Preserve named sides, regions, drawers, slots, outlets, matching positions, and direct relations. A generic location is insufficient; do not assume unmodeled execution supplies a qualifier.
- Enforce the sequence of distinct imperative stages in one workflow, including comma-linked stages ending in `then`, using completed operations. Listing items for the same operation does not order those items or require all to be ready before placing any. Reference order, setup, and hand choice may differ.
- If any source is allowed, do not require an exact source.

## 2. Initial evidence ledger

Before simulation, record only positively supported task-relevant initial facts: each held object/free hand, direct source/support, open/closed state, occupied destination, alignment, and device state.

Candidate and Reference are alternative traces from this same initial scene; never execute Reference actions for Candidate. The image governs visible initial possession, direct support, and occupancy. Candidate `Before` facts and PDDL initial facts are claims to verify, not evidence. Reference wording such as `held` or `cleared by` may describe a later transition, not necessarily the initial state; use it only if consistent with the visible image. The image is initial evidence only, never evidence against a later Candidate-created state. Absence in clutter is not evidence.

Spatial relations may coexist. For example, a broom may be both on the floor and against a wall or cabinet; against does not negate on.

## 3. Simulation and certificate

Simulate only Candidate actions. Each `Before` must be created by an earlier Candidate change or match the initial evidence ledger. Track state directly without transitive support shortcuts.

If Reference opens, clears, moves, vacates, frees, or aligns before later use, Candidate needs an equivalent transition unless the ledger already proves that state initially. If Reference later picks an object from an exact destination, that destination remains occupied until Candidate moves the object.

Fail only with both the exact missing contract item or first failing Candidate step and exact positive evidence. Valid evidence includes a clearly visible wrong direct source, held object, occupied hand/destination, blocked container, open/closed state, or Reference-recorded required transition.

Do not fail from 2D overlap/proximity, guessed reach/collision/grasp, flexible-object behavior, ordinary reorientation, hand preference, or ambiguous adjacent supports. Without a concrete certificate, pass only after confirming every contract item.
