Judge whether an embodied robot plan is executable and fully satisfies the instruction.

# Inputs

Instruction:
{instruction}

Ground-truth reference plan:
{kf_plan}

Evaluated plan:
{nl_plan}

Initial scene image: attached.

# Evidence Model

- The Instruction is authoritative about what must be achieved, including any specified object, scope, method, order, final relation, cleanup, or persistence.
- The reference plan is one valid witness. Infer necessary state changes and causal dependencies from it, without requiring its wording, incidental details, or total order.
- The image grounds identities and the initial scene. An unclear image cannot overturn a necessary causal condition established by the reference.
- Other facts are unknown. Reject only when failure follows from input evidence or unambiguous action semantics; do not invent hidden actions or physical constraints.

# Internal Evaluation

Perform these checks in order without exposing a step-by-step chain of thought:

1. Build the complete task contract from the Instruction.
2. Derive only the effects, prerequisites, and partial-order dependencies needed for execution or that contract.
3. Simulate the Evaluated plan from the initial scene, tracking relevant access, possession, direct location, and device state. State persists until changed.
4. At the earliest definitely unsatisfied precondition, fail and do not perform the completeness check. Otherwise, verify the entire contract and report all missing requirements.

Compare state transitions, not text. Accept supported aliases, paraphrases, independent reordering, harmless redundancy, and alternative paths establishing the same necessary states. An action includes its inherent effects, but not separate acquisition, access, relocation, or release. Direct support and containment are typed and non-transitive. Instruction-required methods, tools, quantities, order, and return conditions cannot be replaced by a similar final state.

Before rejecting, verify that the disputed condition is necessary and cite the decisive input evidence in the reasoning.

# Output

Return exactly this JSON object and no additional fields:

{{
  "reasoning": "concise, evidence-grounded verdict",
  "pass": true,
  "feedback": ""
}}

`reasoning` must be non-empty and concise, not a detailed chain of thought. For execution failure, identify the earliest definite violation. For completeness failure, name every unmet requirement.

`pass` must be a JSON boolean. For true, `feedback` must be empty. For false, it must be an imperative repair instruction for the next PDDL round:

- For execution failure, classify the minimal correction as initial state, object binding, precondition, effect, or action order, and state what the repaired plan must establish.
- For completeness failure, require every omission in the goal and a reachable action chain.
- Preserve correct behavior. Do not copy the reasoning or invent unsupported PDDL details.
