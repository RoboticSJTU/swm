# SWM 主实验测试集设计

本文整理截至 2026-09-14 已确定的实验设计，依据 `docs/PROJECT_SPEC.md`、现有 SWM 指令与参考步骤，以及本轮讨论。本文是测试集构建与评测规范，不表示 40 个模板、200 个实例已经完成采集或训练覆盖审核。

本轮确定的规模是 **40 个任务模板 × 每模板 5 个初始状态 = 200 个测试实例**。此前的每模板 3 个状态、120 个实例方案由此更新。仓库中较早的“视觉、复杂度、组合”三个独立子集方案，不作为本轮主实验的组织方式；旧候选只能经过本规范重新审核后复用。

## 1. 主实验的问题与范围

项目训练模型根据当前场景图像和自然语言指令生成 typed PDDL domain 与 problem，再由 solver 搜索计划：

```text
当前场景图像 + 任务指令
          ↓
         VLM
          ↓
   domain + problem
          ↓
        solver
          ↓
      高层任务计划
```

主实验要检验：从机器人操作视频自动构建的训练数据，是否帮助模型把场景状态、任务目标与动作因果关系转化为有效的规划模型，从而提高任务规划成功率。

主要证据来自三个方面：

1. **总体有效性：** 生成的 PDDL 经求解后，计划是否符合独立核实的任务条件并完整完成任务。
2. **视觉状态适应性：** 同一条指令下，初始状态变化后，系统是否正确调整建模及必要操作。
3. **组合泛化：** 组成子任务在 SFT 数据中出现过，但指定组合被留出时，系统是否仍能正确建模并完成任务。

参考规划步数与附加约束数量用于分析能力边界，不另建互斥子集。语言表述鲁棒性不进入本轮主实验，未来可作为附录补充。

计划搜索由 solver 执行。因此长任务上的表现称为“长任务建模与端到端规划能力”，不直接解释为 VLM 自身的长程搜索能力。

## 2. 整体结构与计数单位

```text
                         40 个任务模板
                               │
               ┌───────────────┴───────────────┐
               │                               │
       20 个训练已见结构                 20 个未见组合
       Seen Composition                Unseen Composition
               │                               │
               └───────────────┬───────────────┘
                               │
                    每个模板设计 5 个状态
                    尽量按难度递增排列
                               │
                               ▼
                         200 个实例
                               │
           ┌───────────────────┼───────────────────┐
           │                   │                   │
     总规划成功率        视觉状态适应性          复杂度分析
     Overall /           同指令不同图片         短 / 中 / 长
     Seen / Unseen       五个状态是否都正确     少 / 多附加约束
```

| 项目 | 数量与含义 |
|---|---|
| 已见结构组 | 20 个模板，100 个实例 |
| 留出组合组 | 20 个模板，100 个实例 |
| 每模板 | 同一条指令、5 张对应不同初始状态的图像 |
| 总计 | 40 个模板，200 个图像—指令实例 |
| 每个状态序号 | 全集 40 个实例，每个组合组 20 个实例 |

这 200 个实例同时参与三类分析，不重复计数。40 个模板也不是 40 个物体名称或 40 条不同措辞的指令。

五个状态增加模板内的状态覆盖和成组评测信息，但不是五个完全独立的任务结构。统计分析应保留模板内相关性；200 个实例的数量本身不保证差异显著。

## 3. 术语与变化的层级

### 3.1 任务族、模板和实例

- **任务族（family）：** 用于覆盖分析的较宽任务类别，例如液体转移、抽屉收纳、微波加热、清洗擦拭。
- **任务模板（template）：** 在语义角色层面定义核心目标、组成子任务及其依赖关系。指令要求的最终状态和附加约束也是模板语义的一部分。
- **状态实例（instance）：** 某个模板在具体对象与初始场景下的一次测试，输入是一张图像和该模板的固定指令。
- **对象实例变化：** 保持相关类别与操作语义兼容，替换具体物体，例如将训练中的碗 A 换成测试中的碗 B。
- **表述变化：** 图像和任务语义不变，只改写语言。本轮不设置该变化。

模板应按目标语义区分，而不是按图像、文本、预测的 PDDL 名称或某一条参考动作序列区分。

| 变化 | 是否新增模板 | 实验含义 |
|---|---|---|
| 同一倒水目标，碗由正放变倒扣 | 否 | 初始状态适应性 |
| 同一倒水目标，瓶子由无盖变有盖 | 否 | 初始状态适应性 |
| 碗 A 换成操作条件相同的碗 B | 否 | 对象实例迁移 |
| 放置任务中的苹果换成香蕉，操作语义不变 | 否 | 对象替换 |
| “倒入液体”变成“倒入液体，再加热并归位” | 是 | 子任务结构变化 |
| 同一目标换一种措辞 | 否 | 语言表述鲁棒性，留待附录 |

如果替换对象改变了必要操作语义，例如任务从切苹果变成剥香蕉，就不再是单纯的对象实例替换。增加收尾要求可改变任务语义，但不能仅靠逐条追加“归位、关门”等要求凑足模板数；总体仍应覆盖不同的核心操作与依赖结构。

初始状态可以改变正确计划，却不改变任务模板。例如“先扶正碗，再倒水”与“直接倒水”属于同一倒水模板的不同状态实例。这正是需要保留的受控对照。

### 3.2 Seen 与 Unseen 的定义

本实验中的见过或未见过，一律相对于**冻结后的实际 SFT 训练数据**，不对基础模型的预训练经历作无法核实的断言。

- **Seen Composition（已见结构）：** 测试模板的目标及子任务结构在实际 SFT 数据中有明确覆盖。测试图片、具体 episode 与状态实例仍必须独立于训练数据。
- **Unseen Composition / Held-out Composition（留出组合）：** 所需子任务和相关操作语义在 SFT 中有覆盖，但指定子任务组合及依赖关系在 SFT 数据中被留出。

主表使用 Seen / Unseen Composition。若使用 OOD 术语，只将第二组明确称为“相对于 SFT 的 Compositional OOD”。不将第一组直接称为整体 ID，因为它仍可能包含新的物体实例、场景、视角和视觉风格。

新图片不等于新组合，新物体名称也不等于新组合。没有完成训练审核的模板只能留在候选池，不能先贴 Unseen 标签进入正式集。

## 4. 对象实例与五个状态的设计

### 4.1 变化发生在哪一层

默认设计是：**对象实例变化发生在训练与测试之间；初始状态变化发生在同一模板的五个测试实例之间。**

例如训练使用碗 A，测试使用 SFT 未出现过的碗 B。同一模板的五张测试图尽量固定碗 B、瓶子 C、工具、设备、拍摄位置与无关背景，再改变任务相关状态。

两组都尽量采用新的对象实例，并保持相近的对象外观差异和场景条件。不能只让 Unseen 组使用新物体或陌生设备。相关新对象仍应具有训练中已覆盖的操作语义，否则会把新操作能力混入组合泛化。

未见对象身份需要通过独立采集来源及训练数据审核支持；仅检查文件哈希不同，不能证明物体不同。无法核实的对象不宣称已完成实例级留出。需要例外时记录实际情况，不用不确定标签填入人工 GT。

新对象提供的是迁移条件，不保证更难。如果没有“训练已见对象”的匹配对照，只能报告系统在新对象上的表现，不能单独估计对象替换造成的性能下降。

### 4.2 五个状态的构造原则

五张图应对应五种有任务意义的初始配置，尽量按必要准备操作或因果依赖增加的方向排列：

1. 目标对象基本可直接操作。
2. 增加一个明确的前置状态要求。
3. 引入另一种准备要求，尽量使处理负担不低于状态 2。
4. 组合前面的状态要求。
5. 在组合基础上增加有依据的阻挡、容纳关系或操作顺序依赖。

这是一种构造思路，不是要求所有任务机械添加相同障碍。优先保留可解释的对照关系，再追求难度排序。不把模型实测失败率用于事后重排状态。

`state_rank = 1...5` 表示模板内预期难度顺序，不是跨模板统一难度标签。相邻状态允许参考步数相同；不能为了严格递增而添加无关动作、不合理障碍或改变指令目标。

每个模板的五个状态至少应覆盖不同的任务相关事实与必要操作差异。纯粹平移物体、换颜色、换视角，或者同一状态重复拍五次，不满足本轮状态覆盖目标。

### 4.3 一个五状态示例

固定指令：`Pour the water from the bottle into the yellow bowl.`

使用同一个新瓶子、同一个新黄碗和相同场景物体。透明收纳盒也始终出现在场景中；下表只是待采集的设计示例，不是对现有 task ID 的重新标注。

| 状态 | 瓶子 | 黄碗及周围条件 | 需要建立的关键条件 |
|---|---|---|---|
| S1 | 瓶盖已取下 | 正放在台面 | 可直接进行取瓶、倒水 |
| S2 | 瓶盖关闭 | 正放在台面 | 先开盖，再倒水 |
| S3 | 瓶盖已取下 | 倒扣在台面 | 先将碗扶正，再倒水 |
| S4 | 瓶盖关闭 | 倒扣在台面 | 同时完成开盖与扶正 |
| S5 | 瓶盖关闭 | 倒扣在关闭的透明收纳盒内 | 先开盒、取出并扶正碗，同时处理瓶盖 |

S1/S2 与 S3/S4 提供瓶盖状态对照；S1/S3 与 S2/S4 提供朝向对照；S4/S5 增加容纳与访问条件。收纳盒必须足够透明，目标碗与状态在输入图像中能明确识别。

实际拍摄后应核实上述条件确实影响合法操作。如果存在无需处理所设障碍的合法替代方案，就不能把指定准备动作强制写成唯一正确答案。固定单臂或双臂、抓持容量等执行假设，避免将资源设定差异误判为模型错误。

### 4.4 采集与可判定性

- 同模板五条指令逐字符相同，物体指称在每张图中都明确且唯一。不要改变颜色名称来迁就不同对象。
- 关键状态和操作所需位置应在图像中可核实，不用模糊、遮挡或分辨率降低来人为制造难度。
- 锁定、温度、内部内容等不可直接观察的事实，只有在固定指令中明确提供或存在预先公开的设备规则时才能依赖；不能只对评测者提供隐藏事实。
- 指令已经说明的状态可以用于任务规划，但不能作为模型通过视觉识别该状态的证据。例如 task_31–32 已说明抽屉上锁，task_78 已说明锅内装满水。
- 不把需要完整演示视频才能知道、而图像和指令没有提供的信息写成硬性评分条件。
- 主集选择可解且仍需操作的任务。目标已完成、不可解任务、主动感知任务不另行加入本轮范围。
- 同模板优先使用同一实物场景的五次布置。无法形成可信对照的跨来源图片留在候选池，不强行填满五状态配额。

## 5. 组合留出与训练数据审核

组合单元是具有完整任务语义的子任务，例如“将液体倒入容器”“加热容器中的内容物”“清洗物体”“收纳物体”。不能仅以 `pick`、`place`、`close` 等动作名称的连续字符串定义组合是否未见。

典型组合是：训练包含“倒奶到杯中”和“加热已经装有液体的杯子”，测试要求“倒奶到杯中，再加热并归位”。前一子任务建立后一子任务所需状态，并共享杯子及其内容物。

优先选择有这种状态连接的组合，避免主要依靠互不相关任务的简单并列。已见组也应包含训练中覆盖过的复合任务，不能让已见组全部为短任务、未见组全部为长任务。

正式入选之前，对每个模板执行以下审核：

1. 固定实际用于 SFT 的导出样本集合及其源视频映射。仅出现在原始候选视频中、但未进入 SFT 的子任务，不计为训练已见。
2. 按子任务目标、对象语义角色及依赖关系归一化模板；为每个必需子任务提供具体训练样本或源 episode 证据。
3. Seen 模板提供完整结构的训练覆盖证据。Unseen 模板检查完整组合、语义等价改写，以及训练中更大任务内是否已包含同一组合关系。
4. 核查所有中间状态增强、语言增强和相关导出版本。按原始视频分组隔离，不能随机拆分同一视频的增强样本到训练与测试。
5. 检查独立视频是否包含等价组合；仅隔离一条测试源视频还不够。动作链检索可用于发现候选，最后按语义核实，不能以未匹配到字符串直接证明组合未见。
6. 对五个状态中新引入的操作也检查训练覆盖。不能让 S5 所需的新设备操作成为 Unseen 组独有的额外变化。
7. 将训练快照、覆盖证据、检索范围、等价性判断及排除记录保留在审核记录中。训练集发生变化时重新审核划分。

如果训练已经包含某个拟留出的组合，可将其作为 Seen 候选，或重新设计训练留出并重新训练；不能在不改变训练事实的情况下改名为 Unseen。

本轮只将**子任务组合留出**作为分组依据。训练中分别出现“开盖”和“扶正”，测试同时出现有盖瓶子与倒扣碗，可以另行研究状态条件组合泛化，但不因此自动改变本轮的组合标签。

## 6. 任务内容与现有样本的复用

现有 `instructions_swm.json` 包含 100 条任务、70 种不同的指令文本。前 30 条共有 7 种指令；task_16–17 的开电脑与 task_18–19 的合上屏幕属于不同目标。文本去重数量不等于模板数量。

现有数据作为候选池，按下表整理。表中的新组合只是内容方向，未经训练审核不能标记为 Unseen，也不表示表内所有方向必须入选。

| 任务族 | 现有任务线索 | 模板与子任务组合方向 | 可选初始状态变化 |
|---|---|---|---|
| 液体转移与工具使用 | task_1–5、20–25、74–77 | 倒水、用勺盛汤、倒入后搅拌 | 瓶盖、锅盖、容器朝向、工具位置、容器访问条件 |
| 取放与抽屉收纳 | task_6–15、31–35、91–92 | 放到目标支撑面、收纳、取出后归位或重新锁闭 | 覆盖、容器开闭、物体来源、明确阻挡；锁态须有可用证据 |
| 微波加热 | task_26–30、36–41、73 | 加热并归位、倒入后加热、加热后恢复设备状态 | 容器是否可用、奶瓶盖、门状态、目标是否被覆盖 |
| 接水、烧水与供水 | task_46–50、54–60、71–72、78–80、93–94 | 接水归位、装水后加热、烧水后倒入目标容器、取水浇植物 | 盖子、可见插头连接、取水容器位置与朝向 |
| 清洗与擦拭 | task_61–70、86–88、97 | 清洗后放置、湿润工具后擦拭、擦拭后丢弃或收纳工具 | 工具可达性、目标叠放、容器朝向、水龙头可见状态 |
| 洗衣与物料添加 | task_42–45 | 投放衣物后加料并启动、取出洗毕衣物并收纳 | 机门、投料抽屉、瓶盖、目标物访问条件 |
| 切割与食品处理 | task_81–85、88 | 放到工作面后切割、清洗后切割或收纳 | 工作面是否放平、容器盖、工具是否可取 |
| 装盒、冷藏与制冰 | task_89–90、95–96、98–100 | 装盒后存入冰箱、加水后启动设备、取物后使用 | 盒盖、柜门、设备盖、支撑物朝向与物体访问条件 |

覆盖原则：

- 两个组合组尽量覆盖相近的任务族、对象迁移条件、子任务数量与参考长度范围；不强制每个任务族分配完全相同配额。
- 同一任务族不能通过颜色替换或重复搬运数量变化占据大量“新模板”。例如同样逻辑搬运三件与五件物体主要是规模变化。
- 保留必要的简单状态测试，也保留多子任务、多收尾要求的任务。仅有开关电脑等少数操作的模板，如果无法自然构造五个有效状态，可替换而不是硬加障碍。
- 数量、容纳关系或清洁目标必须明确。例如“全部”“三个冰块”的范围与计数应可评分。
- “开始洗衣/制冰”与“洗完/制冰完成”是不同目标；不能统一要求所有设备结束时关闭。按指令和公开操作语义判定。
- 加热、煮沸等过程需要明确高层抽象。不能将现实中的“按下启动”无条件视为“已经加热完成”；参考与候选使用同一公开的过程语义。

现有参考步骤需要复核，不能将演示中的每一步都当作唯一正确动作，也不能直接用未经统一的步骤行数比较难度。现有 100 条不一定全部进入最终 200 条；扩建工作不是机械追加 100 条。

40 个具体模板及其 Seen/Unseen 名单，需要在训练审核后冻结。本文不凭指令表虚构训练覆盖证据。

## 7. 复杂度定义

### 7.1 参考长度 L

`L` 定义为统一高层动作粒度下，经审核参考计划的动作数，不使用被测模型生成计划的长度，也不使用指令字数、PDDL token 数或谓词数量。

参考步骤以一次明确的高层操作为单位，例如抓取、放置、扶正、打开门、倒入液体。抓取与放置分开；可拆卸盖子与铰链门按实际操作区别处理。同一种动作在所有模板中使用相同拆分规则。无需加入底层轨迹点或无任务意义的移动。

参考计划应去除无关动作，允许合法的独立动作换序。未经最优性证明，只称“参考长度”，不称“最短长度”。长短划分第一版采用：

| 长度组 | 参考长度 |
|---|---|
| 短 | 1–5 步 |
| 中 | 6–10 步 |
| 长 | 11 步及以上 |

这是构建阶段的工作阈值。完成动作粒度统一与长度分布检查后，在正式评测前冻结；若覆盖不足，优先补足合格模板或明确调整并记录阈值，不根据模型表现移动边界。每个分组同时报告实例数和模板数。

### 7.2 附加约束数量 C

本轮 `C` 专指：在核心目标之外，独立要求的收尾条件、显式额外顺序条件或全程保持条件数量。每条按可独立违反的语义要求计数。

例如将“倒奶并加热”作为核心目标时，“杯子最终回到台面”“微波炉门最终关闭”“奶瓶盖最终盖回”可分别计为三条附加要求。不要把“设备最终恢复”这样的合并句人为算成一条。

不计入 C 的项目：

- 瓶子有盖、碗倒扣、门被阻挡等初始事实。
- 倒水前必须开盖、加热前必须满足设备操作条件等基本可执行性要求。
- 核心子任务本身及其固有因果依赖，例如液体必须先倒入才能加热其中的液体。
- 人为拆细的同义要求或模型自己生成的 precondition。

这些条件仍参与正确性评分，只是不混入附加约束计数。所有任务都适用的公开执行规则也不反复计数。

核心目标与附加要求的划分在模板审核时固定；同类语义要求按相同规则处理，不能为调整难度分组而在 `goal` 与 `constraints` 之间移动。较早候选中的 `implicit_constraint_count` 统计隐含准备要求，与本文 C 的含义不同，不能直接沿用数值或合并比较。

少约束设为 `C = 0–1`，多约束设为 `C ≥ 2`，在正式评测前检查覆盖并冻结。GT 中保存明确的约束条目，C 由条目数计算，不由标注者另填一个数字。

**同模板五条指令相同，所以本设计下 C 通常保持不变。** 状态递增主要改变准备操作与 L，并不要求附加约束数量随 S1→S5 增加。通过增加指令要求制造第五个状态，会破坏同指令对照。

### 7.3 分析方式

先分别报告长度组与约束组的成功率，不强制填满“组合 × 五状态 × 长度 × 约束”的交叉配额，也不合成一个缺乏依据的总难度分数。

长计划可能主要来自重复搬运，短计划也可能涉及关键阻挡或资源依赖。长度、附加约束与状态序号都不能完全代表规划难度。如果长任务也恰好约束更多，只能报告相关趋势；要区分独立影响，需要额外匹配对照。

## 8. 数据格式与文件职责

### 8.1 保持现有输入结构

继续沿用现有图像、指令和参考步骤组织，正式构建时仅补充一个分组元数据文件和一个最小人工契约文件。本文只定义格式，不创建这些数据文件，也不改变现有 task ID 或 PDDL。

```text
tasks/
├── images/swm/<task_id>.<ext>       # 场景图像，保留实际扩展名
├── instructions/instructions_swm.json
├── steps/steps_swm.json
├── metadata_swm.json               # 拟新增：模板与实例分组
└── contracts_swm.json              # 拟新增：独立人工评分契约

eval_results/gt/swm/<task_id>/       # 已有参考产物位置
├── kf_actions.txt                  # 适用时保留源动作证据
└── roundN/
    ├── domain.pddl
    ├── problem.pddl
    └── plan.txt
```

需要分组元数据，是因为现有指令 JSON 无法表达模板归属和组合划分；需要独立契约，是因为仅验证候选自己的 PDDL 不能判断真实任务是否完成。参考与运行输出继续沿用已有目录，不增加新的调度或配置系统。

以下 JSON 是相互对应的格式示例，`task_101`、`template_01` 仅为示例 ID，不表示该图片、参考计划或训练证据已经存在。它们描述上文倒水模板的 S1；正式五状态数据需补齐五个不同实例。

### 8.2 指令与参考步骤

`tasks/instructions/instructions_swm.json`：

```json
{
  "swm": {
    "task_101": "Pour the water from the bottle into the yellow bowl."
  }
}
```

`tasks/steps/steps_swm.json`：

```json
{
  "swm": {
    "task_101": [
      "Pick up the water bottle from the counter.",
      "Pour water from the bottle into the yellow bowl."
    ]
  }
}
```

步骤文件保存经审核的一条可行参考计划，用于任务理解和参考长度计算；不作为候选动作序列的逐项匹配答案。固定执行规则若要求额外归位或收尾，应在所有相关参考与评分中一致落实，而不是对个别候选临时添加。

### 8.3 分组元数据

`tasks/metadata_swm.json`：

```json
{
  "templates": {
    "template_01": {
      "family": "liquid_transfer",
      "composition_split": "seen",
      "structure": "Transfer liquid from a source bottle into a target bowl."
    }
  },
  "instances": {
    "task_101": {
      "template_id": "template_01",
      "state_rank": 1,
      "image": "tasks/images/swm/task_101.jpg"
    }
  }
}
```

- `family` 用于检查任务族覆盖，不决定 Seen/Unseen。
- `composition_split` 正式数据只允许 `seen` 或 `unseen`，并与冻结训练快照的审核结论一致。
- `structure` 使用简短的语义角色描述，对复合模板明确子任务连接关系，不填写某状态专有的开盖、扶正动作。
- `state_rank` 是预先设计的模板内顺序，五个实例各占 1–5，不按 task ID 推断模板关系。
- `image` 为仓库相对路径，解决已有 JPG/PNG 并存的问题。
- 不在该文件重复指令、图像内容、参考步骤、L、C 或模型得分。

训练快照标识、子任务覆盖证据、组合排除记录、对象来源与测试去重结果保存在构建审核记录中，不塞进人工 GT。本例为突出最小数据结构不展示这些记录，但正式发布时必须可以追溯，不能只保留一个未经证据支持的分组标签。

### 8.4 最小人工 GT

`tasks/contracts_swm.json` 的建议结构如下。模板级目标与附加约束共享，实例级只标记关键初始事实，避免将相同目标重复五次：

```json
{
  "templates": {
    "template_01": {
      "goal": [
        "Water from the source bottle has been transferred into the yellow bowl."
      ],
      "constraints": []
    }
  },
  "instances": {
    "task_101": {
      "initial_facts": [
        "The source bottle contains water and its cap is detached.",
        "The yellow bowl is upright on the counter and its opening is unobstructed."
      ]
    }
  }
}
```

`goal` 表达独立评分目标；`constraints` 每项是一条可独立核查的附加要求；`initial_facts` 只保存影响合法操作的关键事实，不转录整张图像。这里使用明确的语义陈述，不要求模型复用一套固定 PDDL predicate 名称，也不是直接可执行的 PDDL。

人工契约遵守以下边界：

- 每条事实和要求必须明确可判定，不使用 `unknown`，不把猜测作为事实。
- 不重复存储图像、原始 instruction、参考动作列表或可由程序算出的长度、数量和得分。
- 没有列出的事实表示未在这个最小契约中作断言，不按 PDDL 闭世界假设自动视为 false。
- `constraints: []` 明确表示没有模板专属的附加约束，不表示没有基本物理或动作规则。
- 必要对象指认若有歧义，先修正拍摄或指令；不通过不断扩张人工注释补救不充分输入。
- 共享契约只适用于目标和约束相同的五状态。若某图无法满足共享目标，修正或替换该实例。

人工 GT 是独立评分依据，不等于一套完整世界动力学。真实操作语义仍需结合审核后的 reference、公开执行规则与人工判定核实。不能仅凭“满足这几条目标字符串”放过不合理的动作效果。

### 8.5 派生数据与评测输出

分析时按 ID 连接输入、元数据、GT 与参考步骤，再计算：`reference_length = len(steps)`、`constraint_count = len(constraints)`、长度组和约束组。这些字段可以出现在程序生成的分析表中，不回填人工 GT。

运行输出按模型和实例保存生成的 PDDL、solver 结果、计划、trace 与最终判断。主结果至少能区分“解析成功”“求解成功”“独立任务判定成功”，失败原因用简短证据说明，不在 GT 内保存候选得分。

现有 GT PDDL 或 problem 一旦修改，必须重新求解并覆盖对应 `plan.txt`，核实新计划与对应 `kf_actions.txt` 完成同一任务；不能手工改旧计划中的动作名。遵守本次修改要求的 round 范围，不顺带改旧 round。

## 9. 评分协议与指标

### 9.1 固定评测条件

主实验默认每个实例一次 PDDL 生成，再调用固定配置的 solver。所有比较模型使用相同输入、提示信息范围、生成预算、solver 版本、时间限制与执行语义。记录具体配置和随机种子。

模型只获得图像、固定任务指令及统一的系统要求；不获得参考步骤、GT、状态序号、组合标签或难度标签。不将训练数据生成阶段的 Judge 修正闭环自动带入主评测。

若未来测多轮修正，另行报告固定轮次和资源预算下的结果；不能把若干次中最好的一次混入单次主结果。测试 GT 不能反馈给模型用来修正。正式集冻结后不用于选择 checkpoint、调提示或修改规则；使用独立开发集完成这些工作。

### 9.2 独立任务成功的定义

实例成功必须同时满足：

1. PDDL 能解析，类型声明、引用、动作绑定符合项目的 typed PDDL 要求。
2. 在预定 solver 预算内得到计划，候选模型内的回放与目标检查通过。
3. 候选中任务相关的对象、初始事实、目标和动作语义与独立输入证据及契约一致。
4. 计划在这些独立条件下可解释为合法高层操作，达到全部核心目标，并满足附加约束。

语法失败、求解失败、超时及任务语义失败都计入主指标分母。基础设施故障应保留记录并按统一规则重跑，不能静默删除困难样本。

候选 solver 成功只证明在候选自己的模型中可解。如果候选把倒扣碗写成正放、漏写归位目标，或使用没有合理前置条件的“万能完成”动作，即使求解成功也不能通过独立任务检查。

允许不同动作命名、合理动作拆分、独立操作换序和其他因果等价计划。无需逐字匹配 PDDL、trace 或参考动作序列；合法但不最短的计划也可成功，冗余不自动等于失败。

### 9.3 独立判定的实施边界

优先使用可信 reference 中的语义映射、回放和契约检查。候选自行生成 operator 时，不能直接按动作名称把计划塞入 reference domain；映射必须保持实际前置条件与状态变化含义。

没有可靠自动语义映射或仿真器时，以独立人工审核作为任务语义终判，隐藏模型身份，依据冻结契约判断，分歧经复核形成明确结论。自动 Judge 可以辅助定位问题，但主成功率不能仅由训练数据生成时同一 Judge 的通过率替代。

人工判定检查计划及其 domain/problem/trace 的因果解释，而不只是看最终目标文本。输入本身无法判定的情况应在冻结前修复；若正式评测后发现数据缺陷，应公开修订并对所有模型统一重评，不能选择性剔除某模型失败项。

本协议得到的是“独立审核的高层任务规划成功率”。没有真实机器人执行时，不命名为机器人真实执行成功率；没有形式化外部世界模型时，也不将人工或多模态语义判定说成物理可执行性的形式证明。

### 9.4 总规划成功率

记模板 t 的第 s 个状态是否成功为 `y[t,s] ∈ {0,1}`：

```text
SR_all    = sum(y[t,s]) / 200
SR_seen   = Seen 组成功实例数 / 100
SR_unseen = Unseen 组成功实例数 / 100
```

正式主表建议列为：

| Model | Overall SR | Seen SR | Unseen SR | 五状态全通过率 |
|---|---|---|---|---|
| 比较模型 | 评测后填写 | 评测后填写 | 评测后填写 | 评测后填写 |

三项 SR 和 All5 均以百分比展示。SR 的计数单位是实例，All5 的计数单位是模板，表注中明确各自分母；不得将二者直接相加或混为同一成功率。

解析成功率与 solver 成功率作为辅助诊断。它们同样以全部测试实例为分母，若另报告条件成功率必须说明分母。

每模板实例数相同，所以实例平均与模板成功率的宏平均相同。以后若补充集数量不同，不将更多变体隐式转换为更高模板权重。

### 9.5 视觉状态适应性

主要指标为五状态全通过率：

```text
All5 = 满足 y[t,1] = ... = y[t,5] = 1 的模板数 / 40
```

Seen 与 Unseen 组可分别计算，分母各为 20。另报告每个模板成功 0/1/2/3/4/5 个状态的分布，以及 S1–S5 各自的成功率，辅助解释 All5 的严格性。

该指标要求整组持续正确，不能由五次产生相同错误获得高分。它也会受总体能力影响，不能单独作为模型利用视觉的因果证明。结合成组案例检查是否正确识别并处理开盖、扶正、访问条件等状态变化。

不要求五条计划文字都不同；要求每条计划对对应状态合法。S1–S5 的分数曲线体现预期状态复杂化下的表现，不把序号视为统一的物理难度单位。

### 9.6 复杂度与统计报告

按短/中/长、少/多附加约束分别报告成功率、实例数和覆盖模板数。若某组过小，展示实际数量并收敛结论，不再细拆出大量小格子。

模型之间使用同一批实例作配对比较。置信区间以模板为聚类单位重采样，保留同模板全部五个状态；总体分析可在 Seen/Unseen 内分别抽取模板以保持分组比例。模型差值使用同一次模板抽样保持配对关系。长度子组分析也保留原模板归属。

报告 95% 置信区间，分析实现时记录重采样次数和随机种子。该区间反映当前模板样本上的不确定性，不消除人工选取任务族带来的覆盖偏差。每组只有 20 个模板，不能因共有 100 张图就声称有 100 个独立组合。

All5 与此前三状态全通过率严格程度不同，不直接比较数值。五状态设计增加覆盖，不保证 All5 提升，也不保证某个预期难度级别的得分一定更低。

## 10. 预期分析结论与必要证据

以下是实验可以检验的问题，不是预先确定的正面结果。结果不支持时，应如实报告失败模式及适用范围。

| 待检验结论 | 需要的证据 | 不能直接外推的结论 |
|---|---|---|
| SFT 数据提高有效任务规划能力 | 基础模型与完整 SFT 模型在相同协议下的独立 SR 差值及区间 | 不能由此确定流水线中哪个环节贡献最大 |
| 系统能处理同目标下的不同视觉状态 | All5、每模板成功状态数、关键状态条件的成组案例 | 不能仅由计划文本变化证明视觉理解；无图对照才提供额外证据 |
| 系统能迁移到 SFT 留出的子任务组合 | 训练覆盖/留出审核、Unseen SR、可比条件下与基线的差异 | 不能声称预训练也未见，或已实现任意组合泛化 |
| 系统在新对象实例上仍能完成任务 | 两组的独立对象来源和训练审核、对应 SR | 无旧对象匹配对照时，不能估计对象变化的独立影响 |
| 性能随参考长度或附加约束变化 | 固定分组下的 SR、样本覆盖及失败原因 | 未控制混杂时，不能声称长度或约束具有独立因果影响 |
| 模型学到了对当前任务有用的 PDDL 建模 | 外部任务条件、动作语义及计划均通过审核 | 单任务通过不能证明 domain 在任意新 problem 上通用 |

最少的模型对照是基础模型与完整 SFT 模型使用同一 VLM→PDDL→solver 形式。若要归因到具体方法组件，复用本测试集进行训练消融：

- 中间状态增强是否有效：有/无该增强，检查总体及状态适应性指标，并控制或明确训练预算差异。
- Judge 筛选是否有效：有/无该筛选，在其他条件可比时检查独立 SR；样本量变化需要控制或说明。
- 语言增强是否有效：留待附录的表述变体及对应消融，不在本轮主结果中宣称。

Seen 与 Unseen 来自不同模板，组间差距仍可能包含任务结构差异。两组成功率均有价值，但只有完成长度、任务族等可比性检查后，才谨慎解释为组合留出带来的泛化差距。

错误分析优先围绕实例的实际失败证据：语法/类型、求解、初始状态或对象绑定、目标遗漏、动作语义或顺序、收尾约束。它们是结果诊断，不是新的测试集类别。

## 11. 构建顺序与冻结条件

1. **确定训练快照。** 列出实际 SFT 样本及源 episode，完成任务级语义覆盖检查；不要先采完 200 张图再判断 Unseen。
2. **整理模板候选。** 合并现有对象替换、同义指令和状态变体，选出目标 20 Seen + 20 Unseen；平衡任务族与复杂度覆盖。名单未审核完时保留数量缺口，不靠改名凑数。
3. **设计并采集五状态。** 每模板固定指令和尽量相同的测试物体，预先写清状态差异、必要操作影响及预期顺序，再拍摄或匹配可信来源。
4. **建立最小 GT 与参考。** 独立核实目标、附加要求、初始事实和合法参考计划，统一动作粒度；适用时重新生成并求解 reference PDDL。
5. **完成独立复核。** 检查图像可判定性、训练/测试泄漏、对象身份依据、五状态对照，以及所有新引入操作的训练覆盖。
6. **计算分布并冻结。** 根据参考生成 L/C，确认两组覆盖及难度阈值，冻结数据、训练快照、评分规则、solver 与推理协议；保留修订记录。
7. **运行并报告。** 所有比较模型评测相同 200 个实例，报告总体、组合分组、五状态适应性和复杂度分析，公开缺陷与不确定性。

正式集验收时应满足：

- 恰有 40 个语义区分明确的模板，20 Seen、20 Unseen，每模板恰有五个实例，状态序号为 1–5。
- 同模板五条指令完全相同；图像确有任务相关状态差异，指令和状态不矛盾。
- 图像、指令、参考步骤、metadata 和实例 GT 的 ID 一一对应；模板 GT 与 metadata 模板一一对应；路径存在，JSON 可解析。
- 每条 Seen/Unseen 标注都对应冻结训练集的审核证据；同源视频和增强版本没有泄漏，Unseen 子任务本身有覆盖。
- 所有人工 GT 明确可评分，没有 `unknown`，没有冗余输入副本或人工填写的派生数字。
- 每个参考计划合法且完成共享目标；所有修改过的 reference PDDL 都重新求解，计划与动作证据任务等价，并保留正确 round 范围。
- 分组与阈值在查看正式模型结果前确定；不足或例外如实记录，不根据模型失败临时修改答案。

## 12. 暂不纳入主实验的内容

本轮不新增语言改写、多语言、无图输入、不可解任务、目标已完成任务、未知操作类别或专门的新环境分组。这些不是当前 200 个实例之外的配额要求。

未来语言鲁棒性实验可从冻结主集预先选择约 20–30 个实例，每个增加两条语义与信息量相同的改写，复用图片和 GT，并报告平均成功率与三表述全通过率。不得删减约束、增加隐藏步骤提示或将目标指令改成完整操作清单。该补充实验不改变主集 40 模板、200 实例的统计口径。

本轮主线始终是：**在尽量采用新对象实例的测试场景中，比较已见结构与留出组合，并检验系统能否根据同一目标下的五种初始状态生成正确的高层计划。**
